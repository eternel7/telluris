## 1. Voie urbaine : s'établir dans une Cité-État

Le personnage arrive dans une ville existante — qu'il s'agisse d'une cité, d'une capitale ou d'une autre grande agglomération.

Il peut progressivement investir dans son **lieu de vie personnel**, mais son développement reste limité par le cadre urbain existant.

**Chambre**  
→ **Logement**  
→ **Maison**  
→ **Maison aménagée**  
→ **Demeure**  
→ éventuellement **Domaine**

Le **Domaine** représente alors la limite de développement personnel dans une Cité-État.

Le personnage peut posséder une propriété importante, employer des PNJ et disposer de plusieurs fonctions, mais il ne devient pas lui-même fondateur d'une nouvelle ville.

### Ce que permet cette voie

Les PNJ peuvent progressivement occuper des fonctions :

- domestique ;
- intendant ;
- garde ;
- marchand ;
- boucher ;
- cuisinier ;
- alchimiste ;
- apothicaire ;
- médecin ;
- érudit ;
- etc.

Le personnage peut donc créer autour de lui une **petite maisonnée organisée**.

- marché ;

- ateliers ;
- port ;

- portail.

Le personnage **profite de la civilisation existante** plutôt que de la construire.

### Limite importante

Il ne peut pas transformer son domaine en village indépendant au milieu de la ville.

Il est propriétaire d'un domaine **à l'intérieur d'une structure politique préexistante**.

Cela donne une voie assez naturelle pour un personnage qui veut devenir :

> **riche, influent, commerçant, propriétaire ou notable.**

Mais pas nécessairement dirigeant d'une communauté.

# 2. Voie de colonisation : fonder un hameau

L'autre voie commence lorsque le personnage quitte les territoires urbains pour s'installer dans un lieu de type **pays**.

Il peut alors obtenir ou choisir un terrain suffisamment éloigné d'une Cité-État pour y établir sa propre implantation.

La première étape n'est plus une demeure.

C'est un :

> **Hameau.**

Le joueur devient alors progressivement **fondateur et administrateur d'un lieu**.

### Progression possible

**Terrain / campement**  
↓  
**Hameau**  
↓  
**Hameau développé**  
↓  
**Village**  
↓  
**Bourg**  
↓  
**Petite ville**  
↓  
**Ville**

Chaque étape augmente les possibilités de construction, de population et de gestion.

---

## Le hameau

Au départ, le personnage possède simplement un lieu relativement rudimentaire.

Il peut :

- construire son logement ;
- stocker des ressources ;
- accueillir quelques PNJ ;
- recruter des travailleurs ;
- organiser l'approvisionnement ;
- sécuriser les environs ;
- établir des cultures ou élevages ;
- construire quelques bâtiments.

Le personnage n'est plus seulement propriétaire d'une maison.

Il possède désormais **un lieu qui peut attirer d'autres habitants**.

---

## Le hameau développé

Le lieu commence à devenir une véritable communauté.

Le joueur peut faire venir :

- agriculteurs ;
- éleveurs ;
- bûcherons ;
- chasseurs ;
- marchands ;
- artisans ;
- aubergistes ;
- médecins ;
- gardes ;
- etc.

Les bâtiments deviennent progressivement spécialisés :

- habitation ;
- entrepôt ;
- ferme ;
- étable ;

- atelier ;
- poste de garde ;
- chapelle ou temple ;

Le joueur doit alors commencer à gérer **une population**, et non plus uniquement ses propres PNJ.

# 3. La fortification devient une mécanique centrale

Dans Telluris, ce développement est particulièrement cohérent avec la dangerosité du monde.

Un hameau isolé est vulnérable.

Il doit progressivement être :

**protégé → fortifié → défendu.**

On pourrait avoir :

**palissade**

→ **enceinte fortifiée**

→ **mur**

→ **portes fortifiées**

→ **tours**

→ **forteresse**

La défense n'est donc pas uniquement esthétique.

Elle conditionne la possibilité pour la population de s'installer durablement.

Un hameau situé dans une région dangereuse pourrait avoir besoin d'une garnison ou de gardes avant d'attirer certains habitants.

---

# 4. Le passage au village puis à la ville

À mesure que le joueur développe son implantation, certains seuils sont franchis.

Par exemple :

### Hameau
Quelques familles et infrastructures essentielles.

### Village
Population permanente, production locale et premiers commerces.

### Bourg
Économie diversifiée, marché, auberge importante, artisans et administration.

### Petite ville
Fortifications, quartiers spécialisés, services nombreux et population importante.

### Ville
Infrastructure complète et véritable pouvoir économique et politique.

À partir d'un certain niveau, le lieu peut donc devenir **une nouvelle ville de Telluris**.

Et c'est là que la seconde voie rejoint ton objectif initial.

---

# 5. La création de la Guilde d'Aventuriers

La **Guilde d'Aventuriers** devient une conséquence du développement de la ville, et non simplement un bâtiment que le personnage peut acheter n'importe où.

Le personnage peut commencer comme aventurier indépendant.

Puis :

> **Aventurier → propriétaire → fondateur → administrateur → fondateur de guilde.**

Une fois son implantation devenue suffisamment importante, il peut créer une **Guilde d'Aventuriers**.

Cette guilde peut alors devenir une institution majeure de la nouvelle ville.

Elle peut :

- recruter des aventuriers PNJ ;
- former des groupes ;
- proposer des missions ;
- gérer les récompenses ;
- employer des spécialistes ;
- stocker du matériel ;
- gérer des contrats ;
- explorer les donjons environnants ;
- sécuriser les routes ;
- participer à la défense de la ville ;
- attirer de nouveaux habitants.

La boucle devient donc :

**Aventurier**  
↓  
**Propriétaire**  
↓  
**Fondateur d'un hameau**  
↓  
**Développement de la communauté**  
↓  
**Ville**  
↓  
**Guilde d'Aventuriers**  
↓  
**Ville prospère grâce à l'exploration**

## Les deux voies en parallèle

| | **Voie urbaine** | **Voie de colonisation** |
|---|---|---|
| Départ | Cité existante | Territoire de type pays |
| Premier objectif | Posséder un logement | Fonder un hameau |
| Progression | Chambre → Demeure → Domaine | Hameau → Village → Bourg → Ville |
| PNJ | Personnel et spécialistes | Habitants + travailleurs + spécialistes |
| Gestion | Patrimoine personnel | Communauté |
| Construction | Aménagement d'un bien | Développement d'un territoire |
| Défense | Assurée par la ville | À construire progressivement |
| Économie | Profite des infrastructures existantes | Doit être développée |
| Population | Pas réellement contrôlée | Croît avec le développement |
| Limite | Domaine | Ville |
| Guilde | Impossible à fonder comme institution propre | Possible une fois la ville suffisamment développée |
| Finalité | Devenir un notable / propriétaire influent | Devenir fondateur et dirigeant d'une communauté |

Cela crée surtout une différence de **fantasme de progression** très nette :

**Voie urbaine :**  
> *« Je deviens quelqu'un dans le monde existant. »*

**Voie de colonisation :**  
> *« Je construis une nouvelle partie du monde. »*

Et la seconde est particulièrement intéressante pour Telluris, car une ville fondée par le joueur pourrait finir par avoir **son propre portail, ses propres aventuriers, ses propres commerces et ses propres problèmes de sécurité**. Elle deviendrait alors un véritable point du réseau des Cités-États, plutôt qu'une simple résidence améliorée.

Dans Telluris, la civilisation existe précisément parce que **les hommes ont appris à créer des poches de sécurité dans un monde dangereux** : les Cités-États ont leurs remparts, les routes leurs Paladins et les portails leurs Templiers.

## 1. Le principe : le campement n'est jamais totalement sûr

Le premier campement pourrait être considéré comme une **zone de sécurité précaire**.

Le joueur choisit un emplacement, et cet emplacement possède des caractéristiques :

- proximité d'une route ;
- proximité d'une source d'eau ;
- terrain défendable ;
- visibilité ;
- ressources disponibles ;
- présence de monstres ;
- proximité d'une tanière ;
- activité magique ;
- distance d'une Cité-État ;
- distance d'un relais ou d'un poste paladin.

Le choix du terrain devient ainsi déjà une décision stratégique.

Un campement installé dans une clairière fertile peut être excellent pour l'agriculture mais très mauvais défensivement. Un campement installé sur une hauteur rocheuse peut être difficile à développer mais beaucoup plus facile à défendre.

---

# 2. La sécurité devrait être une valeur dynamique

Je mettrais une **valeur de sécurité du lieu**, qui n'est jamais simplement « oui/non ».

Par exemple :

**Sécurité : 62 / 100**

Elle dépend de plusieurs facteurs :

### Défense physique
- palissade ;
- fossé ;
- portes ;
- tours ;
- éclairage ;
- bâtiments défendables.

### Défense humaine
- nombre de gardes ;
- qualité des gardes ;
- présence d'un aventurier puissant ;
- présence éventuelle de Paladins ;
- capacité à organiser une garde nocturne.

### Environnement
- distance des zones dangereuses ;
- présence de monstres ;
- routes fréquentées ;
- relief ;
- visibilité.

### Logistique
- nourriture ;
- eau ;
- médicaments ;
- réserves ;
- capacité à remplacer les équipements.

### Connaissance du territoire
- cartographie ;
- zones explorées ;
- tanières identifiées ;
- routes sécurisées.

Cela permet une progression très naturelle :

> **campement vulnérable → campement surveillé → campement fortifié → village sécurisé → ville fortifiée.**

---

# 3. La nuit doit réellement changer la situation

Je pense que c'est une mécanique importante pour faire ressentir la dangerosité de Telluris.

Le joueur ne devrait pas simplement passer de « jour » à « nuit » avec un filtre visuel.

La nuit pourrait provoquer :

- réduction de la visibilité ;
- apparition de certains monstres ;
- augmentation du risque d'embuscade ;
- difficulté à détecter les mouvements autour du camp ;
- nécessité d'organiser des tours de garde.

Au début, avec seulement quelques habitants, le problème est concret :

> **Qui monte la garde pendant que les autres dorment ?**

Le joueur pourrait assigner :

- lui-même ;
- un compagnon ;
- un PNJ garde ;
- plusieurs PNJ en rotation.

Et chaque garde signifie qu'un personnage **ne peut pas faire autre chose pendant cette période**.

---

# 4. Le feu devient une mécanique intéressante

Le feu peut avoir deux effets contradictoires.

### Avantages

- éclairage ;
- chaleur ;
- cuisine ;
- moral ;
- dissuasion de certains prédateurs.

### Inconvénients

- visible de loin ;
- attire certaines créatures ;
- signale la présence du campement ;
- consomme du combustible.

Cela donne des choix très simples mais évocateurs :

> **Feu important et confortable :** meilleur confort, mais campement visible.

> **Feu réduit :** économie et discrétion, mais conditions de vie moins bonnes.

---

# 5. Les monstres ne devraient pas simplement « apparaître »

Pour rendre le monde crédible, je ferais fonctionner les monstres comme une **faune territoriale**.

Un territoire possède par exemple :

- une tanière ;
- une zone de chasse ;
- un territoire ;
- des points d'eau ;
- des migrations.

Le campement peut donc progressivement devenir un élément du territoire.

Au départ :

> « Il y a des loups dans cette forêt. »

Puis :

> « Les loups ont remarqué le campement. »

Puis :

> « Ils attaquent régulièrement les troupeaux. »

Puis :

> « Leur tanière a été localisée. »

Le joueur peut alors décider de :

- protéger les animaux ;
- poser des pièges ;
- chasser les loups ;
- déplacer le bétail ;
- engager des aventuriers ;
- demander de l'aide à des Paladins.

Cela donne une vraie raison d'explorer **autour** du campement.

---

# 6. La menace doit progressivement s'éloigner du camp

Une mécanique que je trouve particulièrement adaptée serait celle de la **sécurisation du territoire**.

Le campement possède une petite zone autour de lui.

Au départ :

**Campement**

→ environnement immédiat inconnu

→ zones dangereuses

→ monstres

Le joueur explore.

Il élimine certaines menaces.

Il cartographie les environs.

Il établit des chemins.

Il installe éventuellement des postes de garde.

La zone sécurisée s'étend progressivement.

Visuellement, on pourrait avoir :

**Zone habitée**  
→ **zone sécurisée**  
→ **zone surveillée**  
→ **zone connue**  
→ **zone sauvage**  
→ **zone inconnue**

Cela matérialise parfaitement la progression du joueur.

---

# 7. Les routes deviennent cruciales

C'est là que les Paladins peuvent devenir extrêmement utiles.

Le joueur construit un chemin entre son hameau et une Cité-État.

Au départ :

> chemin dangereux.

Puis il peut :

- nettoyer la route ;
- construire des relais ;
- placer des postes de garde ;
- faire patrouiller des gardes ;
- payer une escorte paladine.

Cela correspond directement au fonctionnement historique de Telluris : les Paladins existent précisément pour rendre les routes praticables et escorter les voyageurs.

Une colonie isolée devient donc beaucoup plus viable lorsqu'elle est **connectée à une route sécurisée**.

---

# 8. Le campement doit avoir des besoins vitaux

Je limiterais volontairement les ressources fondamentales à quelques catégories.

### Nourriture
Consommée quotidiennement.

### Eau
Indispensable et dépendante du terrain.

### Bois
Construction et combustible.

### Matériaux
Construction et réparation.

### Médicaments
Soins et maladies.

### Mana
Plus tard, surtout lorsque la colonie commence à utiliser des infrastructures magiques.

Cela permet de créer des problèmes très concrets :

> « Nous avons suffisamment de nourriture pour 12 jours, mais seulement 4 jours de bois. »

ou :

> « La récolte est bonne, mais notre source d'eau est devenue dangereuse. »

---

# 9. Les blessures et maladies

La dangerosité ne devrait pas se résumer aux combats.

Une colonie isolée pourrait subir :

- blessures ;
- maladies ;
- intoxications ;
- accidents ;
- morsures ;
- infections ;
- épuisement.

Le recrutement d'un **médecin**, d'un **apothicaire** ou d'un **alchimiste** devient alors une amélioration de sécurité, pas simplement un service économique.

Cela donne également de la valeur aux PNJ.

# Telluris RPG — Implémentation de la voie urbaine des lieux de vie

## Contexte

Je développe Telluris, un RPG stratégique 2D médiéval-fantastique.

Le joueur incarne un aventurier qui peut progressivement s'établir dans les Cités-États existantes.

Je souhaite maintenant implémenter **uniquement la voie urbaine du système de lieux de vie**.

La voie urbaine représente le développement du patrimoine personnel du personnage dans une ville ou une capitale existante.

Elle ne doit **pas** permettre de fonder une communauté, un village ou une ville. Cette progression appartiendra à une future mécanique distincte de colonisation.

Le personnage peut progresser approximativement selon cette logique :

**Chambre → Logement → Maison → Maison aménagée → Demeure → Domaine**

Le **Domaine constitue la limite de la voie urbaine**.

---

# 1. Objectif général

Créer un système permettant au personnage :

- d'acheter ou louer un lieu de vie ;
- de dormir dans ce lieu ;
- de récupérer ;
- de stocker ses objets ;
- d'améliorer progressivement son lieu ;
- d'y accueillir des PNJ ;
- d'employer certains PNJ ;
- de fournir à ces PNJ des espaces de travail ;
- de gérer les activités réalisées par les PNJ ;
- de développer son patrimoine sans jamais fabriquer directement des objets lui-même.

Le système doit être conçu de manière suffisamment générique pour pouvoir être étendu ultérieurement à la voie de colonisation et à la Guilde d'Aventuriers.

---

# 2. Principe fondamental : le PJ n'artisane pas

Le personnage joueur **ne fabrique pas lui-même les objets**.

Il peut :

- acheter des objets ;
- commander des objets ;
- fournir des matières premières ;
- employer des PNJ ;
- gérer des PNJ ;
- donner des ordres ;
- utiliser les services produits par les PNJ.

Les métiers d'artisanat et de commerce appartiennent aux PNJ.

Exemples :

- boucher ;
- alchimiste ;
- apothicaire ;
- cuisinier ;
- marchand ;
- médecin ;
- artisan ;
- érudit ;
- intendant ;
- domestique ;
- etc.

Le lieu de vie permet donc progressivement d'accueillir ces PNJ et, lorsque le lieu possède les infrastructures nécessaires, de leur permettre d'exercer leur métier.

# 3. Hiérarchie des lieux

Implémenter les niveaux suivants :

## Niveau 1 — Chambre

Premier niveau accessible.

Fonctions :

- dormir ;
- récupérer ;
- stocker une quantité très limitée d'objets ;
- définir ce lieu comme résidence actuelle du personnage.

La chambre peut être une chambre louée dans une auberge ou un établissement équivalent.

Elle ne permet pas d'employer de PNJ professionnel.

Elle ne permet pas de développer une activité économique.

---

## Niveau 2 — Logement

Premier espace appartenant éventuellement au personnage ou loué pour une longue durée.

Fonctions :

- dormir ;
- récupérer ;
- stockage supérieur à celui de la chambre ;
- accueillir ponctuellement un PNJ ;
- disposer d'un espace personnel plus important.

Le logement doit pouvoir être amélioré ultérieurement.

---

## Niveau 3 — Maison

Le personnage dispose désormais d'un véritable lieu de vie.

Fonctions :

- dormir ;
- récupération ;
- stockage important ;
- accueillir plusieurs PNJ ;
- posséder plusieurs espaces internes ;
- commencer à organiser les occupants.

Une maison peut par exemple posséder :

- chambre du personnage ;
- chambres supplémentaires ;
- réserve ;
- cuisine ;
- espace commun.

Ne pas implémenter d'artisanat du PJ.

---

## Niveau 4 — Maison aménagée

La maison peut recevoir des aménagements spécialisés.

Le joueur doit pouvoir ajouter ou débloquer différents espaces.

Exemples :

- cuisine ;
- réserve ;
- bibliothèque ;
- salle de soins ;
- bureau ;
- espace marchand ;
- espace pour un artisan ;
- chambre supplémentaire ;
- salle d'entraînement.

Ces espaces ne servent pas à donner des compétences d'artisanat au PJ.

Ils servent à **permettre à des PNJ spécialisés d'exercer leur activité**.

Exemple :

Un joueur possède une maison aménagée avec un espace adapté.

Il recrute un PNJ alchimiste.

Le PNJ peut alors utiliser cet espace pour exercer son métier, à condition que les autres prérequis soient satisfaits.

---

## Niveau 5 — Demeure

La demeure constitue un patrimoine important.

Elle permet :

- davantage de stockage ;
- davantage de chambres ;
- davantage de PNJ ;
- davantage d'espaces spécialisés ;
- personnel domestique ;
- gestion plus importante des ressources ;
- accueil de visiteurs ;
- organisation plus complexe des occupants.

Le joueur peut commencer à disposer d'une véritable maisonnée.

La demeure doit donner l'impression que le personnage est devenu un individu établi dans la société de la Cité-État.

---

## Niveau 6 — Domaine

Le Domaine est le niveau maximal de la voie urbaine.

Il s'agit d'une propriété importante située **à l'intérieur ou dans l'environnement immédiat d'une Cité-État existante**.

Le joueur peut y gérer :

- de nombreux PNJ ;
- des employés ;
- des spécialistes ;
- plusieurs espaces spécialisés ;
- des réserves importantes ;
- des activités économiques réalisées par les PNJ ;
- l'accueil de compagnons et visiteurs ;
- l'organisation de son personnel.

Important :

**Le Domaine ne peut pas devenir un hameau, un village ou une ville.**

Il reste une propriété privée dépendante de la Cité-État.

La fondation d'une nouvelle communauté appartiendra à un autre système.

## Objectif

Implémenter le système de propriétés résidentielles du joueur.

Le système doit distinguer clairement :

1. **Le type de propriété** : Chambre, Logement, Maison, Demeure ou Domaine.
2. **Les aménagements** : éléments que le joueur peut acheter ou installer dans une propriété.
3. **Les occupants et PNJ** : personnes pouvant vivre, travailler ou être hébergées dans la propriété.

### Principe fondamental

Une propriété possède un **type fixe**.

Les types sont :

**Chambre → Logement → Maison → Demeure → Domaine**

Il ne doit jamais être possible de transformer directement une propriété en un type supérieur.

Exemple :
- une Maison ne peut pas être transformée en Demeure ;
- le joueur doit vendre, abandonner ou quitter sa Maison puis acquérir une Demeure ;
- les aménagements de l'ancienne propriété restent attachés à cette propriété et ne sont pas automatiquement transférés.

Le système doit donc traiter chaque propriété comme une entité indépendante possédant son propre type et ses propres aménagements.

# 6. Règles générales des aménagements

Les aménagements ne doivent pas constituer des niveaux de propriété.

Une Maison fortement améliorée reste une **Maison**.

Une Demeure faiblement aménagée reste une **Demeure**.

Le type de propriété détermine les aménagements qui peuvent être installés.

Exemple :

```text
Maison
 ├── Cuisine
 ├── Bibliothèque
 ├── Salle de soins
 ├── Petit atelier d'artisan
 └── Jardin
```

mais :

```text
Maison
 └── Impossible d'ajouter une grande écurie
     ou un quartier important pour le personnel
     si ces aménagements sont réservés à la Demeure.
```

Les aménagements doivent donc avoir une contrainte de type de propriété.

Exemple de donnée conceptuelle :

```text
aménagement:
    id
    nom
    types_proprietes_autorises
    coût
    prérequis
    capacité
    effets
```

Le système doit privilégier les données existantes et les systèmes déjà présents dans le projet plutôt que de créer des systèmes parallèles.

# 7. Achat, vente et abandon

Une propriété doit pouvoir avoir un état correspondant à sa possession par le joueur.

Le joueur doit pouvoir :

- acheter une propriété ;
- occuper une propriété ;
- quitter une propriété ;
- vendre une propriété lorsque les règles économiques de la ville l'autorisent ;
- abandonner une propriété lorsque cela est pertinent.

**Important : aucune conversion de type.**

Pour passer de :

```text
Maison → Demeure
```

le joueur doit effectuer une nouvelle acquisition :

```text
Vendre/abandonner la Maison
        ↓
Acquérir une Demeure
        ↓
Aménager la Demeure
```

Les aménagements doivent rester associés à leur propriété et ne doivent pas être transférés automatiquement lors de l'acquisition d'une autre propriété.

---

# 8. Interaction avec les PNJ

Le joueur ne fabrique pas directement les objets.

Les propriétés peuvent cependant fournir des espaces permettant à des PNJ d'exercer leurs professions.

Exemples :

- un cuisinier utilise une cuisine ;
- un alchimiste utilise un laboratoire ;
- un artisan utilise un atelier ;
- un médecin utilise un cabinet ;
- un apothicaire utilise une apothicairerie ;
- un marchand utilise un espace commercial ou administratif ;
- un domestique utilise les espaces de service ;
- un garde utilise un poste de garde ou un quartier adapté.

L'existence d'un espace ne doit pas automatiquement créer un PNJ.

Le joueur doit disposer du PNJ approprié pour exploiter l'aménagement.

---

# 9. Séparation avec la colonisation

Ce système concerne principalement les **propriétés dans les cités existantes**.

Il ne doit pas transformer automatiquement une propriété en :

- hameau ;
- village ;
- ville ;
- cité ;
- guilde d'aventuriers.

La création et le développement d'une colonie constituent un système distinct.

Le Domaine représente donc une forme avancée de propriété privée, pas une étape vers la fondation automatique d'une nouvelle cité.

---

# 10. Architecture technique

Avant toute modification :

1. Examiner les systèmes existants concernant :
   - bâtiments ;
   - propriétés ;
   - villes ;
   - inventaires ;
   - stockage ;
   - PNJ ;
   - professions ;
   - commerce ;
   - recrutement ;
   - sauvegarde ;
   - temps ;
   - récupération.

2. Réutiliser les systèmes existants lorsqu'ils peuvent supporter cette fonctionnalité.

3. Ne pas créer de doublon fonctionnel.

4. Les types de propriétés et leurs aménagements doivent être **data-driven** autant que possible.

5. Les limites de chaque propriété doivent être déterminées par sa configuration et son type, et non par une simple condition codée en dur dans l'interface.

6. Les données de propriété doivent être sauvegardées :
   - type ;
   - propriétaire ;
   - état ;
   - aménagements ;
   - occupants ;
   - espaces disponibles ;
   - PNJ affectés ;
   - stockage associé.

7. L'interface doit clairement distinguer :
   - le **type de propriété** ;
   - les **capacités** ;
   - les **aménagements installés** ;
   - les **aménagements disponibles** ;
   - les **PNJ présents** ;
   - les **activités exercées**.

Ne pas implémenter de conversion directe d'un type de propriété vers un autre.

Pour le **mode colonisation**, je distinguerais les ressources disponibles sur le lieu de celles qu'on peut ensuite produire. Pour décrire un site d'installation, les plus intéressantes sont celles qui influencent directement **la survie, la construction, l'économie, la sécurité et le potentiel de développement**.

### Ressources naturelles

- **Eau douce** — rivière, source, lac, nappe accessible.
- **Bois** — quantité et qualité des forêts exploitables.
- **Pierre** — construction, fortifications, routes.
- **Argile** — briques, poteries, construction.
- **Sable** — verre, construction.
- **Métaux** — fer, cuivre, étain, etc.
- **Métaux précieux** — or, argent, éventuellement ressources rares.
- **Charbon / combustible fossile** — énergie et certaines productions.
- **Sel** — conservation et alimentation.
- **Herbes médicinales** — médecine et alchimie.
- **Plantes utiles** — fibres, teintures, matériaux, alimentation.
- **Gibier** — alimentation, cuir, fourrure.
- **Poissons** — alimentation.
- **Animaux domestiquables** — élevage potentiel.
- **Terres fertiles** — agriculture.
- **Pâturages** — élevage.

### Ressources liées au mana

Dans Telluris, je donnerais à ces ressources une catégorie spécifique.

- **Cristaux de mana** — source directe de mana.
- **Concentration de mana** — qualité magique générale du territoire.
- **Sources ou veines de mana** — présence localisée d'une énergie exploitable.
- **Anomalies magiques** — peuvent constituer une ressource ou un danger.
- **Vestiges de portail** — potentiel d'exploitation ou de connexion future.
- **Proximité d'un donjon** — accès potentiel aux ressources d'un donjon, mais aussi risque accru.

### Ressources territoriales

Elles ne sont pas forcément « récoltables », mais peuvent être déterminantes pour choisir un emplacement.

- **Terres cultivables disponibles**
- **Surface constructible**
- **Forêt exploitable**
- **Cours d'eau navigable**
- **Accès à une route existante**
- **Accès à un ancien chemin**
- **Passage naturel** — col, vallée, gué, etc.
- **Position dominante** — colline, hauteur, falaise.
- **Abri naturel** — grotte, vallée encaissée, forêt dense.
- **Accès à la mer**
- **Accès à un fleuve**
- **Proximité d'une cité**
- **Proximité d'un poste paladin**
- **Proximité d'un portail**
- **Proximité d'autres établissements**

### Ressources économiques

Pour une colonie, certaines caractéristiques deviennent des ressources économiques plutôt que naturelles :

- **Potentiel agricole**
- **Potentiel d'élevage**
- **Potentiel forestier**
- **Potentiel minier**
- **Potentiel artisanal**
- **Potentiel commercial**
- **Potentiel de transport**
- **Potentiel de pêche**
- **Potentiel de chasse**
- **Potentiel touristique ou culturel**, si pertinent dans Telluris.
- **Ressources rares** donnant une spécialisation à la colonie.

### Ressources stratégiques

Je les traiterais séparément, car elles déterminent la valeur d'un emplacement même lorsqu'il est pauvre en ressources naturelles.

- **Défensibilité du terrain**
- **Visibilité sur les environs**
- **Contrôle d'un passage**
- **Contrôle d'un pont ou d'un gué**
- **Contrôle d'une route**
- **Éloignement des zones dangereuses**
- **Distance d'une cité alliée**
- **Distance d'un bastion paladin**
- **Distance d'un portail**
- **Distance des territoires connus des monstres**
- **Possibilité de fortification**
- **Possibilité d'étendre progressivement le territoire**

### Pour le gameplay

Je ne mettrais probablement **pas toutes ces ressources sous forme de compteurs**. Pour choisir un site de colonisation, une fiche pourrait plutôt présenter quelques grands axes :

| Catégorie | Exemples |
|---|---|
| **Eau** | Source, rivière, lac |
| **Nourriture** | Fertilité, gibier, pêche |
| **Matériaux** | Bois, pierre, argile |
| **Minerais** | Fer, cuivre, métaux rares |
| **Mana** | Cristaux, concentration, anomalies |
| **Énergie** | Bois, charbon, autres combustibles |
| **Commerce** | Route, fleuve, mer, proximité d'une cité |
| **Défense** | Terrain, visibilité, fortification |
| **Danger** | Monstres, donjons, anomalies |
| **Expansion** | Surface disponible, terrains voisins |
| **Spécialisation** | Ressource exceptionnelle propre au site |

Cela permettrait surtout de donner à chaque emplacement une **identité économique et stratégique**. Un site peut être médiocre pour l'agriculture mais excellent pour le minerai ; un autre peut être pauvre en ressources mais exceptionnellement bien placé sur une route ; un troisième peut avoir une forte concentration de mana tout en étant beaucoup plus dangereux.

Pour Telluris, je pense que le couple **Ressources disponibles + Dangers du territoire** est particulièrement intéressant : le meilleur emplacement n'est pas simplement celui qui possède le plus de ressources, mais celui dont les ressources valent le risque nécessaire pour les exploiter.
